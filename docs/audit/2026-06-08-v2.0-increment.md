## 1. 范围与方法

增量：新模块 M11（api/mock/supabase/client/orchestrator/feature）+ M9 集成（sync hooks + mergeRemote）+ main.tsx 登录 UI + i18n。方法：逐文件重读 + 对齐共识 v2.0 / ADR-013~016 / **security-review rule** / arch-constraints §4/§7，对抗视角找：匿名回归 / 数据隔离 / 同步数据丢失 / 首屏膨胀 / Gateway 边界 / 真impl 未验风险。

## 2. 干净项（正向比对）

- **匿名零回归（AC-v20-1/7）**：env-less → `syncEnv()` 静态 null → `enabled=false` → 无登录 UI + M9 `setSyncHooks` 永不调用 → 本地多文档/离线完全不变。**e2e 93/1skip 全过（env-less）实证**
- **supabase 不进首屏**：env-less build **完全 tree-shaken**（0 字节，dummy-env build 验证 supabase=204KB **独立 lazy chunk**，首屏仅 +1.18KB 为 sync wiring/UI，82.38<150）
- **Gateway 边界守住（arch §7）**：supabase-js 仅 M11/supabase.ts 碰；M9/UI 经接口，mock 可替 → unit 不连真云
- **数据隔离设计基于 identity（arch §4）**：RLS `user_id=auth.uid()`，非业务字段；mock 模拟分区 + UT-RLS-deny 验调用方契约
- **同步数据安全（mergeRemote）**：per-doc LWW + 首登并集（不丢任一侧 / UT-SYNC-merge-union）+ 软删 tombstone 防多设备复活（UT-SYNC-delete-tombstone）
- **FE 不做授权**：FE 仅持 session（UX），授权全在 RLS（ADR-016）
- **本地无 schema 变更 / 无迁移**（软删 cloud-only，比初版方案更简）

## 4. 盲点声明（重大）

- **整个 v2.0 真云路径未跑过**：mock 验逻辑，但"真能登录 + 真跨设备同步 + 真 RLS 拦截"**0 次真实验证**（infra 在用户侧）。这是本版最大盲点，诚实标注，不可当"已工作"
- supabase.ts 的 supabase-js API 用法可能与真实有出入（版本/参数）——research-first 在 provision 时须复核官方文档
- RLS 策略 SQL（data-model v2.0 §1）未在真 Postgres 跑过（语法/策略默认拒绝行为未验）
- 自审自己代码，安全核心尤需第二人 + 真渗透测试（无）

## 5. 结论 + 发布门槛

v2.0 mock 实现**逻辑层无 critical/high**；架构（Gateway/匿名隔离/首屏 lazy）+ 同步数据安全（LWW/并集/tombstone）+ 数据隔离设计（RLS/identity）**设计与 mock 验证到位**。

**但 2 条 MEDIUM（F-V20-1 真impl 未验 / F-V20-2 RLS 真隔离未达）= 安全发布门槛 AC-v20-6 PENDING** → **不打 v1.0.0，打 `v1.0.0-rc.1`**（release candidate）。真验证清单（用户 provision 后）：
1. 开 Supabase 项目 + 跑 data-model v2.0 §1 建表+RLS SQL
2. 配 `VITE_SUPABASE_*`（CI Secrets）→ build（supabase lazy chunk 生效）
3. 真登录（magic link 收信）+ 跨设备同步验（AC-v20-2/3/4/5）
4. **构造两用户验 RLS 隔离（AC-v20-6 / A 不能读写 B）+ 人工审 RLS 策略**
5. magic link 回调 × `#doc=` 共存线上验（F-V20-3）
→ 全过 + security review 签字才升 v1.0.0。
