## 0. 定位

**共识文档 = "系统应该做什么"的单一事实来源。** 相对 PRD 的增量：

- PRD = **产品视角**（为谁做、什么形态、商业逻辑）
- 共识文档 = **工程视角**（系统行为、业务规则、状态机、边界、术语统一）

按 spec-to-code-flow，共识文档**天生可以残缺**——含 [TBD] 标注的待对齐项允许，但必须显式列出，通过反哺机制后续完善。

## 2. 业务术语统一表

PRD 中混用了「编辑器 / 编辑区 / 编辑面板」、「预览 / 渲染 / 效果」、「文档 / 文稿 / 草稿」等——本节统一。

| 标准术语 | 含义 | 同义词（不用）|
|---------|------|------------|
| **编辑区** | 左侧输入 Markdown 源文的 UI 区域 | 编辑器、编辑面板、textarea |
| **预览区** | 右侧实时渲染 Markdown 的 UI 区域 | 渲染区、效果区 |
| **文档** | 用户在编辑区维护的一份 Markdown 内容 | 文稿、草稿、笔记 |
| **持久化** | 内容写入 localStorage 的动作 | 保存、自动保存、暂存 |
| **导出** | 将文档输出为 .md 文件或 HTML 剪贴板 | 下载、保存到本地 |

## 3. 功能模块边界（→ 下游模块清单基线）

| 模块 | 职责边界 | 对应 PRD §4 |
|------|---------|------------|
| **M1 编辑** | 接收键盘输入、维护源文状态、维护字号/行高/行号显示 | F1 |
| **M2 预览** | 监听编辑区状态变更、调用渲染管线、输出 DOM、滚动同步（best-effort） | F2 |
| **M3 持久化** | localStorage 读写、debounce 写入、清空操作 | F3 |
| **M4 导出** | 文件下载（.md）、剪贴板复制（HTML） | F4 |
| **M5 布局** | 桌面双栏 / 移动单栏 tab 切换、响应式断点 | F5 |
| **M6 主题** | 浅深色切换 + 持久化 | F6 |
| **M7 i18n** | UI 字符串抽象层（首版仅中文，预留接入点） | §5 |

依赖图：

```
  M1 编辑 ──→ M2 预览
     ↓         (订阅 M1 变更)
  M3 持久化 ←─ debounce 触发
     ↑
  (页面打开时还原)

  M4 导出 ──→ 读 M1 (源) + 读 M2 (渲染 DOM)
  M5 布局 ──→ 容器层，包含 M1/M2/chrome
  M6 主题 ──→ 装饰层，影响 M5 容器 class
  M7 i18n ──→ chrome 文案层（不影响 M1 内容）
```

## 4. 业务规则细化（PRD 没回答的工程行为）

### 4.1 持久化规则（M3）

| 规则 | 决议 [TBD] |
|------|----------|
| **写入策略** | **debounce(500ms)** — 用户停止输入 500ms 后才写入，避免高频写入磨损 localStorage |
| **多 tab 竞争** | **后写覆盖 + 不提示**（MVP 单文档场景，跨 tab 协同复杂度不值；如需可在 v1.1+ 加 `storage` event 监听）|
| **localStorage 配额满** | 写入抛 `QuotaExceededError` 时 **toast 提示，不降级**到 sessionStorage（让用户感知风险，引导走 v1.1 IndexedDB）|
| **key 命名** | 固定 `editor.document.v1`（v1 留语义版本前缀，未来兼容性变更走 v2） |
| **value 编码** | 纯字符串（Markdown 源文，UTF-8） |

### 4.2 渲染规则（M2）

| 规则 | 决议 [TBD] |
|------|----------|
| **XSS 防护** | **sanitize**（如 DOMPurify 或同等方案）— CommonMark 允许 raw HTML，必须过滤；属安全红线，遵循 `security-review.md`（架构阶段 ADR 锁定具体库）|
| **渲染时机** | M1 状态变更 → 同步触发 M2 重渲染（无 debounce，渲染本身应在 50ms 内完成）|
| **空文档显示** | 预览区显示灰色占位文字「在左侧输入 Markdown，这里会显示预览」 |
| **滚动同步** | **MVP 不做** — v1.1+ 再做行匹配 / 百分比同步，simplify 优先（PRD F2.3 "best-effort" → 实际取舍为推迟）|

### 4.3 导出规则（M4）

| 规则 | 决议 [TBD] |
|------|----------|
| **.md 文件名** | `editor-YYYYMMDD-HHmmss.md`，**本地时区**（匹配用户预期）|
| **.md 内容** | 纯 Markdown 源文（M1 当前内容），无 BOM，LF 换行 |
| **HTML 复制范围** | **innerHTML**（无 outer wrapper）— 用户复制后多用于贴到富文本编辑器 / Slack / Notion，外壳无用 |
| **HTML 内联样式** | innerHTML 不携带 CSS（依赖目标环境样式表）|

### 4.4 主题规则（M6）

| 规则 | 决议 [TBD] |
|------|----------|
| **切换粒度** | 全局（M5 容器加 `data-theme="dark"` class，所有子模块继承）|
| **持久化范围** | **浏览器级**（key=`editor.theme.v1`，所有 tab 共享）|
| **默认值** | 跟随系统 `prefers-color-scheme`，无系统提示时默认浅色 |

### 4.5 i18n 规则（M7）

| 规则 | 决议 [TBD] |
|------|----------|
| **首版语言** | 中文 |
| **抽象层做法** | **MVP 即抽象**（极简方案：内部 dict + `t('key')` 函数 ~10 行代码，避免日后回填成本）|

### 4.6 错误边界与降级

| 场景 | 行为 |
|------|------|
| localStorage 不可用（隐私模式 / 浏览器禁用）| toast 提示「持久化不可用，请勿关闭页面」，编辑功能仍可用 |
| 剪贴板 API 不可用（HTTP 环境 / 浏览器不支持）| F4.2 复制 HTML 按钮显示 toast「复制失败，请手动选择预览区内容复制」 |
| Markdown 解析异常（理论不应发生，但兜底）| 预览区显示「渲染失败：<错误摘要>」，不崩溃 |
| 文档长度极端 | 不限制写入；首次超过 **1MB** 时 toast 一次性提示「内容较长，性能可能下降」|

## 5. 状态机

editor 状态相对简单——主状态机只有 M3 持久化模块有意义：

```
      ┌────────────┐
      │   IDLE     │ (无未保存变更)
      └────────────┘
            │ user input
            ↓
      ┌────────────┐  500ms 无新输入   ┌────────────┐
      │   DIRTY    │ ─────────────────→ │  SAVING    │
      └────────────┘                    └────────────┘
            ↑                                  │
            │ 新输入打断 saving                  │ localStorage.setItem
            │                                  ↓
            │                          ┌────────────┐
            └─────────────────────────│ SAVED→IDLE │
                                       └────────────┘
                                       (失败 → ERROR + toast)
```

UI 不必显式呈现 DIRTY/SAVING——内部状态，仅用于决定是否触发写入。但保留状态机便于 §4.6 错误处理。

## 6. 非功能约束工程语义（细化 PRD §5）

### 6.1 性能基准

| 指标 | PRD 阈值 | 测量条件 |
|------|---------|---------|
| 首屏 | < 1s | 4G 网络 / Lighthouse mobile profile / cold cache |
| Bundle | < 150KB gzipped | production build / 主入口 + 同步依赖 |
| 输入到预览 | < 50ms | M1 Pro / 1000 行 Markdown 内容 / Chrome DevTools Performance |
| 移动端滚动 | 30fps 下限 | iPhone 14 Pro Safari / 500 行内容 |

### 6.2 浏览器兼容性下限

「最近两个大版本」具体含义：以 2026-05-18 为基准，确认时点用「当前 stable 版本 N」+「N-1」两个版本。每 6 个月 review 一次。

| 浏览器 | 当前下限（2026-05-18）|
|--------|------------------|
| Chrome | 134 + 135 |
| Safari | 17.x + 18.x |
| Firefox | 134 + 135 |
| Edge | 134 + 135 |

### 6.3 隐私 & 离线

- 不联网（首次资源加载除外）：架构阶段需用 ADR 锁定「禁止 fetch / WebSocket / 第三方分析脚本」
- 不打点：默认禁用任何 telemetry（即使是默认开启 sourcemap 上传等也要关）
- Service Worker：MVP 不做，明确 v1.1+

## 7. 跨系统约束

**本项目纯 FE / 无后端**——无跨系统集成。如未来引入云同步（v2+），需新建共识文档章节并走 ADR。

外部资源依赖（仅有）：
- 主机静态资源 CDN（部署目标 [TBD]，PRD §8 R3）
- 字体加载（如有自定义字体）：架构阶段决定是否引入
