## 1. 动机与范围

路线图（PRD §7）已全部消化，本版是首个 PM 新拍 scope。核心场景"临时草稿/速记"的日常编辑痛点：找不到刚写的词、加粗要手敲 `**`、列表每行重敲前缀、不知道写了多少字。

**范围（仅）：** M1 编辑区的查找/替换、格式快捷键、列表自动延续、字数统计展示。
**不在本次：** 全文高亮 overlay（textarea 根本限制，见张力 A）/ 正则搜索 / Markdown 工具栏按钮 / 多文档跨文档搜索（v1.8 已有列表过滤）/ TOC（→ v2.2）。

## 2. 张力

### 张力 A — textarea 无法富高亮
查找命中无法像 VSCode 那样全文黄底高亮（textarea 内部不可染色；mirror-div overlay 方案重且与行号/软换行组合爆炸）。MVP 取舍：**跳转 + 原生选区**（`setSelectionRange` 选中当前命中）+ 计数 `n/m`。见 TBD-v21-1。

### 张力 B — 程序化编辑 vs 原生 undo 栈
`setRangeText()` 不进浏览器 undo 历史 → 用户 Cmd+Z 撤不掉"替换/加粗"操作（数据安全级 UX 问题）。`document.execCommand('insertText')` 保 undo 但已 deprecated（无移除时间表，浏览器实测仍全支持）。**HOW 归 ADR-017**，共识层只锁验收：所有程序化编辑必须可 Cmd+Z 撤销（AC-v21-7）。

### 张力 C — 中英混排字数
"字数"对中文=字符、英文=词。混排文档需复合计数，阅读时长两种速率合算。见 TBD-v21-5。

## 5. 验收条件（v2.1 新增 AC，待 test-plan 细化）

- AC-v21-1：Cmd/Ctrl+F → 查找栏出现且聚焦；输入即时计数 `n/m`；Enter/Shift+Enter 下/上一个命中（选区跳转 + 滚动可见）；Esc 关闭回焦编辑器
- AC-v21-2：替换当前 → 仅替换当前命中并跳下一个；替换全部 → 全部替换 + toast 计数
- AC-v21-3：Cmd/Ctrl+B/I 对选区加包裹；再次按 → 解包（toggle）；无选区 → 插入空包裹光标置中
- AC-v21-4：Cmd/Ctrl+K 对选区生成 `[选区](url)` 且光标选中 `url` 占位
- AC-v21-5：列表行回车 → 新行自动补前缀（`1.` 递增、`- [ ]` 重置未勾）；空列表项回车 → 删前缀退出
- AC-v21-6：字数统计随输入实时更新；纯中/纯英/混排计数正确；空文档显 `0 字`
- AC-v21-7：**所有程序化编辑（替换/快捷键/列表延续）Cmd+Z 可撤销**（张力 B 验收锁）
- AC-v21-8：查找/替换/快捷键不破既有行为：行号 gutter 对齐、滚动同步、持久化防抖、移动端单栏

> 无安全门槛：无新外部输入渲染面（查找词不入 DOM innerHTML；所有插入文本走 textarea value → 既有 DOMPurify 管线兜底）。
